1. Usage

    search                       open the TUI
    search [flags] QUERY...      search inline (QUERY may contain !bangs)

    -e, --engine NAME   engine or bang alias: ddg, g, b, k, w, gh, sg ...
    -c, --code          code search
    -t, --type TYPE     web, code, repos or issues
    -l, --lang LANG     code language        -r, --repo OWNER/NAME
    -n, --limit N       results              -p, --page N
    -s, --summary       print the summary    --no-summary
    -j, --json          JSON output          -m, --markdown
    -o, --open          open the search page in a browser
    -1, --lucky         open the first result
    -u, --url           print the search URL
    -i, --tui           open the TUI with the query
    -E, --compose       write the query in $EDITOR
        --edit          open the results in $EDITOR
        --theme NAME    --browser CMD      --config FILE
        --list-engines  --list-bangs       --list-themes
        --example-config
Queries can be piped in: echo "zig allocators" | search -m

2. TUI keys

    / i ctrl+l        edit the query (search bar)
    enter l → space   result details      (enter in details: open)
    j k ↓ ↑           move / scroll       gg G home end  first / last (5G: result 5)
    ctrl+d ctrl+u     page down / up
    esc               in the search bar: normal mode; otherwise back one level
                      (details → results → start page)
    :                 command line (:help commands)
    v / V             visual mode: select text in the details, y copies
    f / F             hints: type a result's label to jump to / open it
    gt / gT           next / previous tab
    h ←               close details
    o / O             open result / search page in the browser
    y / Y / M         copy URL / snippet or code / Markdown link
    e / E             result (page or code file) / all results in $EDITOR
    s                 summarise the page (automatic when details open)
    n N ] [           next / previous page
    tab shift+tab     engine picker (j k ↑ ↓ tab move, letters jump)
    t                 cycle type: web → code → repos → issues
    ctrl+e c          compose the query in $EDITOR
    r                 re-run           ?  help
    q                 close the pane (quit if it is the last)
Panes, as in vim (outside the search bar): 
    ctrl+w s          split: new pane below
    ctrl+w v          vsplit: new pane to the right
    ctrl+w h j k l    focus the pane in that direction
    ctrl+w w / W      next / previous pane
    ctrl+w q / c      close the pane
    ctrl+w o          only this pane
    ctrl+w + - < >    resize            ctrl+w =  equal sizes
    ctrl+w T          move the pane to a new tab
Counts work like vim: 5j, 3G, 2gt. Command line (:), as in vim and iamb. Tab completes, abbreviations work: 
    :q  :qa  :close  :only            quit / close panes
    :sp :vs :new :vnew [query]        split (with a query: search in it)
    :resize [+-]N  :vert resize N     pane sizes
    :vert :aboveleft :tab {cmd}       placement modifiers
    :tabnew :tabc :tabo :tabn :tabp   tabs (also gt / gT)
    :search :engine :type :page       searching
    :open :yank :copy :edit [N]       act on result N
    :summarise :export :compose       pages and $EDITOR
    :help :theme :set :engines        interface
    :bangs :history :version
    :N                                jump to result N
Mouse: wheel scrolls, click selects, click again for details. Rebind anything under [keys], e.g. open = ["o", "enter"]

3. Bangs

A !bang anywhere in the query picks the engine, like DuckDuckGo. In bash and zsh, single-quote queries containing ! (history expansion): 
    search '!so rust lifetimes'

    !g !ddg !b !k !br !m !sx    web engines
    !w !so !hn                  Wikipedia, Stack Overflow, Hacker News
    !gh !ghc !ghi               GitHub repos, code, issues
    !gl !glc !gli !sg !cb       GitLab, Sourcegraph, Codeberg
    !yt !aw !nix !hm !mdn ...   open in your browser
    !                           I'm feeling lucky
search --list-bangs prints all of them. Add your own: 
    [bangs]
    nw = "https://wiki.nixos.org/w/index.php?search={query}"
    work = "gitlab:code"

4. Engines

    duckduckgo   default, no key        bing          no key
    wikipedia    no key                 stackoverflow no key
    hackernews   no key                 sourcegraph   no key (code)
    github       token for code search: GITHUB_TOKEN or gh auth token
    gitlab       token for code/issues  codeberg      optional token
    google       api_key + cx           kagi          api_key or token
    brave        api_key                mojeek        api_key
    searxng      base_url
Engines that need configuration are hidden until it is set; their bangs open the site in your browser instead. Credentials can be literal or come from the environment, a file or a command: 
    [engines.kagi]
    token_file = "~/.config/kagi/session-token"

    [engines.github]
    token_command = "gh auth token"
Or skip the config file entirely: in the TUI, :login {provider} saves credentials in one JSON file (~/.config/search-tui/auth.json, mode 0600, $SEARCH_TUI_AUTH to override) and newly configured engines appear immediately. The argument is required and tab completes provider names. 
    :login kagi      Search API key or Session Link. A Session Link uses your
                     Kagi plan at no extra cost (unofficial HTML interface,
                     possibly bot-challenged); an API key uses the billed v1
                     Search API (~$12/1000). The kind is auto-detected.
    :login github    OAuth device flow: a code is shown, github.com/login/device
                     opens, and the token (repo, read:org, gist scopes) is
                     polled in the background. Uses the GitHub CLI's public
                     OAuth app; SEARCH_TUI_GITHUB_CLIENT_ID overrides it.
    :login google    API key, then the Programmable Search engine ID (cx).
    :login brave     API key (free tier needs a card on file).
    :login mojeek    API key (paid; the HTML endpoint is captcha'd).
    :login gitlab    personal access token with read_api; set
                     [engines.gitlab] base_url first for self-hosted.
Explicit config wins: a literal value, *_env, *_file or *_command in config.toml is tried before auth.json. :help login lists the same notes in the TUI. Custom engines: type = "url" | "json" | "html", or another instance of a built-in type (gitlab, github, searxng, sourcegraph, gitea): 
    [engines.work]
    type = "gitlab"
    base_url = "https://gitlab.example.com"
    token_command = "pass show work/gitlab"
    bangs = ["work"]

5. Configuration

~/.config/search-tui/config.toml ($XDG_CONFIG_HOME is honoured; on Windows %AppData%\search-tui). search --example-config prints a fully commented example. 
    default_engine = "duckduckgo"
    default_code_engine = "github"
    fallback_engine = "bing"        # when a web search fails
    results = 20
    low_power = false
    browser = ""                    # see 7
    editor = ""

    [summary]
    sentences = 3

    [ui]
    theme = "default"
    layout = "auto"                 # auto | split | stacked
    mouse = true

6. Themes

    [ui]
    theme = "nord"
    colors = { accent = "#ebcb8b" }
default, ansi (uses your terminal's palette), mono, catppuccin-mocha, -macchiato, -frappe, -latte, dracula, nord, gruvbox-dark, gruvbox-light, solarized-dark, solarized-light, tokyo-night, tokyo-night-day, one-dark, one-light, monokai, everforest, rose-pine, rose-pine-dawn, kanagawa, github-dark, github-light. Themes only set foreground colours; the terminal background is never painted.

7. Browser and $EDITOR

Links open with --browser, then browser = "...", then $BROWSER, then the system default (xdg-open, open, Windows, termux-open-url). Values are a command with optional %s, or an app name on macOS ("Firefox"); on Windows use the browser's path. Only http(s) links are opened. Terminal browsers such as w3m run inside the TUI. $EDITOR (or editor = "...") is used for composing queries in a temporary Markdown file, reading results and pages as Markdown, and opening the full source of code results at the matching line.

8. Summaries and low power

Summaries are extractive and computed on your device: sentences that agree with the rest of the results and match the query, without repeats. Opening a web result's details fetches and summarises that page automatically, and that page summary is the only summary the TUI shows. For a summary of a whole result set, use the CLI (`search -s`); for an abstractive one, pipe results to a local model: 
    [summary]
    command = "ollama run llama3.2:1b"
low_power = true uses fewer results, smaller download caps and no animations, for very small machines.
